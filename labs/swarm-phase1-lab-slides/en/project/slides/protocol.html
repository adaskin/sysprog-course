The protocol (frozen)

One message per line, plain text

center → leader

ASSIGN id x0 y0 x1 y1 nyour zone
THEME sec start end theme moodcoarse direction
PLAN req nthen n keyframe lines
BUSY req retry_msqueue full, later
BEAT nstart beat n
SHUTDOWNbye

leader → center

HELLO id nI am here
PLAN_REQ req sec n seedgive me a plan
READY id secplan is loaded
POS id beat f x y cwhere f is
ACK id beatbeat done
  • Keyframe line: beat follower x y color. A plan has one for every beat and every follower.
  • Unknown message: log and ignore. Malformed: reject, never crash. Lines are at most 256 bytes.
  • You can test a leader by typing these lines into its stdin.

BIL 322 · Swarm Phase 1 lab

The protocol is a fixed contract. Every message is one plain-text line, so humans and agents can both read it: you can watch a rehearsal scroll by, or type a message into a leader’s stdin by hand to test it. From the center: ASSIGN gives a leader its zone, THEME gives the coarse direction of a section, PLAN carries the detailed choreography as n keyframe lines, BUSY says the request queue is full, BEAT is the clock, SHUTDOWN ends the show. From the leader: HELLO, PLAN_REQ to commission a plan, READY when the plan is loaded, POS and ACK to report where each follower is after a beat. A plan is dense: one keyframe for every beat and every follower. Unknown messages are logged and ignored; malformed ones are rejected and never crash the receiver. The parser is given; you use it.
