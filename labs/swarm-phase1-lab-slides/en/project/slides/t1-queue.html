The bounded queue

queue_t *queue_create(size_t cap, size_t item_size);

int queue_push(queue_t *q, const void *item); // blocks if full

int queue_try_push(queue_t *q, const void *item); // -1 if full

int queue_pop(queue_t *q, void *out); // blocks if empty

void queue_close(queue_t *q); // wake everyone

size_t queue_size(queue_t *q); void queue_destroy(queue_t *q);

Used twice: the center’s request queue (try_push, then BUSY if full) and the leader’s queue of themes.

Rules

  • while, not if, around every pthread_cond_wait
  • After close: pop drains the rest, then returns −1; push returns −1
  • close wakes everyone: broadcast
  • No busy-waiting, no sleep

BIL 322 · Swarm Phase 1 lab

Task 1 is the classic bounded buffer from the lecture: a ring buffer with a mutex and condition variables. Two condition variables, not full and not empty, make the logic easy to read. Items are copied by value, so the same queue holds ints, requests and themes. Use while because of spurious wakeups and because another thread may take the item before you. After queue_close, pop keeps returning the remaining items and then fails, so workers drain the queue and exit; push fails immediately, also for a thread that was already blocked in push. close must wake everybody: broadcast, not signal. No busy-waiting and no sleep. You can test the queue alone with tests/test_queue before the rest of the project exists.
