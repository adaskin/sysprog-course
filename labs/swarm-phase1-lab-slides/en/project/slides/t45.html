BIL 322 · Swarm Phase 1 lab

Task 4: the given grid_swap exchanges two cells and locks both rows. If two threads swap the same pair of rows in opposite orders, each holds one lock and waits for the other: a deadlock. swapstress reproduces it in seconds in row mode; in global mode it does not hang. Show the stuck threads in gdb, name the Coffman condition you break (circular wait, broken by a lock ordering: always lock the lower row first), and explain why your fix cannot cause a livelock. Task 5: the leader started with --battery 1:20 exits when beat 20 starts, as if it crashed. The center must notice through EOF on the pipe, reap the process with waitpid so there is no zombie, close both pipe ends, and wake the clock loop that may be waiting for an ACK from it. With restart (the default) it starts a new captain for the zone: ASSIGN, then THEME from the next beat on. The new troupe starts at home, so the speed audit forgives one jump (skip_speed), but collisions are never forgiven. With --no-restart the zone is just marked gone. In the report: what would be different if the performers were processes? That is Phase 3.
