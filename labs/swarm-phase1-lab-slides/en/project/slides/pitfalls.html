When it hangs

Four traps, and how to see them

A barrier nobody reaches

The barrier is shared by all followers. One early return or continue between the two waits, and everyone else waits forever.

A lock never released

Every unlock must happen on every path. Early returns are the usual leak, in the queue and in serve_request.

The wrong lock order

In the center: wlock first, then st_mu. The same rule fixes grid_swap: always the lower row first.

Hiding a race with sleep

Never. Run make tsan instead, and read the two stacks it prints.

A hang prints center: TIMEOUT after --timeout seconds. Attach with gdb -p PID, then thread apply all bt.

BIL 322 · Swarm Phase 1 lab

Four things that will go wrong this week. One: the barrier is shared by all followers of a leader; if any of them leaves the loop between the two waits, the others wait forever. Two: a lock not released on some path, for example an early return; read your code for every return. Three: lock order. The center’s state lock and the per-leader write lock have a fixed order, commented in center.c; breaking it can deadlock. The same idea fixes the grid_swap deadlock. Four: sleeping to make a race disappear never fixes it; use ThreadSanitizer, which prints the two conflicting accesses. When the show hangs, the watchdog prints a timeout; attach gdb to the process and print all thread backtraces to see who waits for what. That output is also the evidence for the Task 4 write-up.
